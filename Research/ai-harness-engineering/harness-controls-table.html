ThinkInfoSec · AI Harness Engineering through a security lens

The harness is the control plane

Zhong & Zhu's eleven harness components (arXiv 2605.13357, Table 1), with each one's runtime contract, failure mode and evidence quoted from the paper. Each is mapped to the security control it already resembles and the practical control I'd put in place. The paper has no adversary in its threat model, so the dashed twelfth row is my addition, not theirs.

01 · taskTask interface
Present objective, requirements, constraints, success criteria
Underspecified goal; wrong-target work
Task record
Authorised scope. The task is the change request. Text lifted from issues or tickets is untrusted input.
800-53 CM-3OWASP LLM01
Tie every agent run to an approved ticket. Agents never self-assign work from issue text or comments.
02 · contextContext manager
Select and expose task-relevant project content
Wrong-file inspection; missed constraints
Context trace
Indirect prompt injection. READMEs, vendored code, dependency docs and web results all flow straight into the model.
OWASP LLM01
Label context by provenance (first-party, third-party, web). The context trace records which untrusted sources the agent read.
03 · toolsTool registry
Declare available tools and allowed commands
Failed call; unsafe command; repeated timeout
Tool trace
Excessive agency. Each MCP server and shell command widens the agent's blast radius. Tool output is untrusted input.
OWASP LLM06800-53 AC-6
Allowlist tools and commands per task class, with no wildcard shell. Review the registry like a firewall ruleset.
04 · memoryProject memory
Provide agent-readable architecture, testing, known-failure knowledge
Repeated rediscovery; wrong-layer fix
Memory references
Persistent poisoning. Anything one agent writes to memory, the next agent trusts. It works as a stored-injection channel.
OWASP LLM04
Treat memory writes as privileged changes: version them, review them via CODEOWNERS, and never auto-merge agent edits to memory.
05 · stateTask state
Maintain hypothesis, inspected files, open questions, next steps
Drift; repeated work; incoherence
Task-state file
Data handling. Scratch notes collect file contents, env values and stack traces, all of which can leak.
OWASP LLM02
Keep state files in the session sandbox, run secrets scanning on them, and purge or retain them on the same schedule as other change records.
06 · observeObservability layer
Expose logs, traces, outputs, runtime errors
Unverifiable success; un-diagnosable failure
Observation log
Audit logging & provenance. The eight trace types make up an episode package, which is effectively a build attestation.
800-53 AUSLSAEU AI Act Art. 12 (shape)
Attach the episode package to the PR, forward tool traces to the SIEM, and keep them as long as other change records.
07 · attributeFailure attribution
Separate observation, expected behavior, diagnosis
Random patching after failure
Attribution log
Root cause before recovery. This is incident-response discipline. The taxonomy has no adversarial category.
IR / RCA
Add an F_adversarial class so a suspected injection gets escalated, not quietly "recovered" from by a retry.
08 · verifyVerification protocol
Map task requirements to deterministic evidence
Unverified success; false confidence
Verification trace
Change management & verifier integrity. An agent that weakens tests is the party under assessment editing its own assessment.
800-53 CM-3SA-11SSDF SP 800-218
Run requirement checks evaluator-side, where the agent can't edit them. Put tests and CI under CODEOWNERS. "The agent said tests pass" isn't evidence.
09 · permitPermission boundary
Restrict risky actions; expose approval gates
Unsafe invalid episodes
Permission record
Least privilege by another name. The paper gives it one row, so the specifics are left to you.
800-53 AC-6OWASP LLM06
No ambient cloud credentials in the agent's shell. Approval gates on CI config, infrastructure-as-code and dependency manifests. Sandbox with default-deny egress.
10 · entropyEntropy auditor
Detect maintenance burden introduced by the agent
Stale docs; dependency churn; residue
Entropy audit
Attack surface management. A forgotten debug script is a forgotten endpoint, and an unneeded dependency adds a supply-chain link (and slopsquatting risk).
OWASP LLM03SCA
Gate every agent session: new packages, scripts, endpoints and doc changes go through the same SCA and secrets scanning.
11 · interveneIntervention logger
Record human assistance and its avoidability
Invisible human scaffolding
Intervention log
Measurable human oversight. M-HIR = missing-harness interventions ÷ total episodes.
NIST AI RMF Measure/Manage
Log the times a human stopped an unsafe action separately from the times one helped. The stops are security events.
12 · my additionTrust boundary management
Separate trusted instructions from untrusted content across context, memory and tool output
Hijacked agent; self-attested malicious change
Provenance labels
The missing adversary. The paper never mentions prompt injection, secrets, sandboxes or attacks.
OWASP LLM01LLM04LLM06
Broker secrets through short-lived scoped tokens. Require signing or review for memory writes. Keep independent evaluator checks even when the harness is mature.
